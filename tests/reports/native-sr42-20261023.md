# Native SR42 regression evidence

This excerpt contains only generic code behavior and automated regression results.
It excludes operational identifiers, checkpoint hashes, filesystem locations,
capacity figures, host details, account data and private transcripts.

Experiment filing is not sufficient evidence of a checkpoint's scientific method.
The controller regression fixture files a contrastive evaluation under the MSE
experiment and verifies that explicit provenance repairs the seen map. Unknown
active evaluations block dispatch; an unknown completed evaluation of the selected
checkpoint also blocks a duplicate until its provenance can be established.

Python3.6 does not accept the newer subprocess.run text/capture_output arguments.
The helper uses universal_newlines and explicit pipes, and portable unlink
handling. The compatibility regression rejects the unsupported argument shape.

Local transfer storage must not grow with every recurring evaluation. Controller
tests verify that interrupted staging freezes one download, newer checkpoints
remain pending, managed admission is durable before cleanup, and cleanup retries
without another submission. Adapter tests verify private cache selection,
transfer resumption, ownership receipts, digest mismatch refusal and idempotent
removal of only the owned local download. Remote pins and small receipts remain.

The reviewed source passes26 focused tests. The additive Operations overlay passes
65 integration tests covering scheduling, authorization and managed admission.
Independent review approved the implementation and these regression checks.
Trainer recovery still requires separately verified source and checkpoint parent;
passing these tests does not establish any training run's health.
